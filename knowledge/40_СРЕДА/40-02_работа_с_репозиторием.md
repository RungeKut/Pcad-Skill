# Работа с репозиторием

Набор — `https://github.com/RungeKut/Pcad-Skill`, ветка `main`.
**Порядок, обезличивание, стоп-лист, автор, соавторы, форк и разбор PR —
соседний скилл skill-skill, `knowledge/40_СРЕДА/40-02`; GitHub без `gh` —
там же, 40-03.** Коротко: в начале `git -C <корень> pull --rebase`; после
правки `git diff` глазами → `python tools/check_docs.py --project "<папка
проекта>"` → `git add <файлы>` → `git commit` → **`git push` сразу**.

## Обезличивание: схемы

Кроме общего списка, в набор, текст коммита и PR не попадают:

* названия и децимальные номера изделий, **имена цепей и позиционные
  обозначения** конкретной схемы, типы и номиналы её компонентов, их
  атрибуты;
* пути к схемам и их имена — в том числе в тестах и примерах: схема для
  `tests/test_dump.py` и `tools/dbx-host/poc.py` задаётся аргументом, а не
  в коде;
* выгрузки схем (`tests/vyvod/`, не под git) и снимки окон Sch.exe.

Остаётся: поведение P-CAD и DBX, вызовы `pkit`, ловушки, примеры на
отвлечённой схеме (`D:\проект\схема.SCH`, `A1`, `GND`).

Имена файлов P-CAD (`.sch`, `.pcb`, `.lib`) из папки проекта
`check_docs.py --project` превращает в стоп-слова (`tools/kit_local.py`).
Папку проекта можно запомнить для клона:
`git config pcad.project "<папка проекта>"` — её учитывают и
`check_docs.py`, и хук.

**Исполняемые файлы в PR** — `tools/dbx-host/DbxHost.cs`, `build.bat`,
`*.py`: после слияния собираются и запускаются на машине владельца,
читать их особенно внимательно.
